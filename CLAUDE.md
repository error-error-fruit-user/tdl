# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`tdl` is a ratatui terminal launcher for UZDoom: named profiles (ordered wad lists), one-key launch, and host/join multiplayer where the host serves its wad list over HTTP on port 8080 and joiners download missing wads. User-facing docs are in `README.md`; the on-disk layout is in `DATA_LAYOUT.md`; planned work is in `secrets/TODO.md` (local, untracked).

## Commands

Requires **nightly** Rust (`#![feature(associated_type_defaults)]`, edition 2024).

- Build / run: `cargo +nightly build --release`, `cargo +nightly run -- [--session] [--[keep-]loadout DIR | --[keep-]forget-loadout] [--wads DIR... | --keep-[loadout-]wads DIR... | --[keep-]forget-wads] [--[keep-]uzdoom FILE] [--[keep-]base-wad FILE] [--[keep-]ini FILE] [--[keep-]theme FILE] [--[keep-]splash FILE] [--unseal SCROLL | --unseal-delete[-force] SCROLL] [--no-splash] [--splash-quip QUIP | --no-quips] [[--music SONG] [--keep-music] | --no-music] [(launch PROFILE | host PROFILE | join IP) [--headless]] [--seal SCROLL [--with-settings]] [--with-pride]` (`--help` for the full list; flags are parsed by clap in `src/cli.rs`, its help colored from the worn theme). A plain flag asks whether to keep what it gives (`cli::Keep::Ask`), `--session` makes every plain flag just for the run, and a `--keep-` flag keeps without asking even with `--session`; the launcher's `offer_to_keep` asks and `keep_unasked` keeps.
- Tests: `cargo +nightly test`; single test: `cargo +nightly test <name_substring>`
- UI tests are `insta` snapshots (`src/**/snapshots/*.snap`). Review changes with `cargo insta review` (or `INSTA_UPDATE`) rather than hand-editing.
- `upgrade_legacy.py` (dependency-free Python 3.8+, its own MessagePack codec) upgrades the files of a tdl before 1.0.0, which tdl itself no longer reads; `loadout/legacy.rs` finds them at startup and tells the user to run it, and its tests run the script end to end on a file of every historical shape (they skip if there is no `python3`).
- `./demo_screenshot.sh` records `demo.gif` and `docs/screenshots/` with vhs (`demo.tape`, `screenshots.tape`).
- `./publish.sh` cross-builds the Windows release (`x86_64-pc-windows-gnu`) into `published/` (with `upgrade_legacy.py`) and generates `THIRD_PARTY_LICENSES.txt` (needs `cargo-license`). Crates that ship no license file get theirs from `licenses/` (by crate name, or the part before the first `-`); the script fails, naming them, if any has none.
- Version control is **jj** (colocated with git). `secrets/commit.sh "msg" [--claude]` commits and moves the `main` bookmark; use `--claude` for work Claude helped write (adds the Co-Authored-By trailer). `secrets/push.sh` pushes `main` using the token next to it. Both run from anywhere in the project.

## Architecture

- **`ritual.rs`** is the UI framework core. The `Ritual` trait is the screen/popup abstraction: `render(&mut Frame)`, `prompt(grimoire, key) -> Phase<T>` (`Render` / `Prompt` / `Return`), and `invoke` runs the event loop until a value is returned. Ctrl+C becomes `Error::Interrupted`, which unwinds out of every nested ritual. It also holds the shared window helpers (`conjure_window`, `conjure_veil`, `conjure_sigil` for the `[?]` legend hint). The file (and parts of the codebase) uses a deliberately themed vocabulary via `as` aliases (Grimoire = Terminal, Costume = Frame, Chant = KeyCode, Omen = Result, etc.); follow the existing style in that file instead of "normalizing" it.
- **`screens/`** are full-screen rituals (launcher, editor, splash, host settings, join address, pickers). **`popups/`** are small modal rituals (dialog, three-way dialog, progress, status, warning, legend, resize notice). Screens nest popups by calling `.invoke(grimoire)` on them. **`widgets/`** are reusable drawing pieces, and `widgets/text.rs` is the one text-editing helper every typed field uses (cursor, arrows, Home/End). The launcher and editor share `screens/search.rs` (ranked search, history), `screens/selection.rs` (`Shift+V` ranges, `M` marks, moving rows) and the session-only `clipboard.rs`; `tag.rs` numbers copies (`brutal_2`). Settings are `screens/settings.rs`, all kept in `loadout/uac.rs` (`Uac`, saved as `uac.rite`; it was `global.rite` before 1.0.0, and code and docs still call these "the global settings"), as are UZDoom, the base wad, the ini, the theme's path and the last host port; a loadout's `config.rite` holds only its profile order and kept wad dirs. Forms (`widgets/form.rs`) scroll to keep the focused field in sight. `quips.rs` and `music.rs` hold global switches (`quips::show`, `music::mute`/`start`/`stop`). `screens/library.rs` is the wads screen (`L`): it works on an owned `loadout/shelf.rs` `Shelf` (wad dirs, kept dirs, file moves), which `Loadout::restock` applies afterwards, since the editor can't borrow the loadout mutably while it is open.
- **`slayer/`** (`host_game.rs`, `join_game.rs`, `share.rs` for `.scroll` export and import, whose format is `loadout/scroll.rs`, `watch.rs` for profiles that watch a dir) orchestrates the multiplayer and sharing flows end to end, using `net.rs` (address, join codes, name safety) and `net/` (`manifest.rs`, `serve.rs` with the tiny_http server, `download.rs` with ureq downloads and BLAKE3 verification) and `uzdoom.rs` (building the command line and spawning the game, capturing `session.log`).
- **`loadout/`** is persistence. A *loadout* (called the vault before 1.0.0) is one pair of config and data dirs. `Loadout` holds the config dir and data dir plus the loaded `Config`, `Profile`s and `Uac` settings, and writes through on every mutation (except reordering, saved on launcher quit). `scribe.rs` does atomic writes (`.tmp` then rename, `.bak` of the previous version, unreadable files renamed `.corrupt` and never overwritten). `wad.rs`/`hash.rs` track wads by path plus content hash so moved/changed/volatile wads show as placeholders instead of breaking the whole profile.
- **`layout.rs`** sizes every window from its content and shrinks it to the terminal (minimum 40×20); long lists scroll. **`theme.rs`** holds the `Theme` struct (colors, styles, borders, glyphs and help colors) and its built-in default; `theme/splash.rs` (`splash.toml`: logo, tagline, hint, quip, fire) and `theme/pride.rs` (`pride.toml`: pride fire and flags) dress the splash screen. All three implement `theme/dressing.rs`'s `Dressing`: TOML with an `edition` key (missing means 1; breaking changes append a `fn(&mut toml::Table)` to `UPGRADES`, never edit or reorder them; newer editions are refused), partial files fall back to the built-in values, unknown keys are errors, and each is worn through a `Wardrobe` (`theme::worn()`, `theme::splash::worn()`, `theme::pride::worn()`). The built-in splash and pride are also `assets/splash.toml`/`assets/pride.toml` (what **New** writes); tests keep them equal to the Rust defaults, and parse every TOML example in `THEME.md`/`SPLASH.md`, which document every field: update them with any field change. Screens ask for roles, never a color directly; main wears the kept theme before clap parses, so `--help` is themed too.
- **`testing.rs`** (`#[cfg(test)]`) provides `draw(width, height, scene)` for rendering to text for snapshots and `example_loadout` (the same three example profiles used in the README screenshots).

## Saved-file format rules

Everything in `uac.rite` / `config.rite` / `.profiles/*.rite` (and `.scroll`s) is MessagePack wrapped as `{version, data}`, via the `Edition` trait in `src/loadout/edition.rs`. Each type's `Edition::FIRST` is the edition tdl 1.0.0 wrote (uac 2, config 5, profile 4, scroll 1); anything older is legacy (`Loaded::Legacy`, never read, moved or upgraded by tdl) and belongs to `upgrade_legacy.py`. Adding a `#[serde(default)]` field is not breaking. Any change that alters what existing data means (rename, retype, unit or default change) is breaking and requires: an upgrade fn `vN_to_vM`, **appended** to the type's `Edition::UPGRADES` (never reorder, edit or remove entries; the version number is `FIRST` plus the list length), and a test that loads a file saved by the previous edition. Update `DATA_LAYOUT.md` when the file contents change.

The in-memory types and the saved shapes differ on purpose: `Wad` keeps a whole `OsString` path in memory, but saves through `loadout/saved.rs` (`SavedPath` text, `SavedWad`), and `Profile` saves through `SavedProfile` (a dir table plus `(dir, name)` per wad) via `#[serde(try_from/into)]`. `SavedPath` and `SavedEntry` are `#[serde(untagged)]` so a path that isn't valid UTF-8 can fall back to the OS's own form (`Native`) and a wad without a dir to `Loose`. Never serialize a bare `OsString`: serde tags it `Unix`/`Windows` and the other OS can't read it back. `Loadout::lookup()` is an `Option` built lazily (only joining uses it) and is dropped by `insert`/`replace`/`remove`/`forget_lookup`.
